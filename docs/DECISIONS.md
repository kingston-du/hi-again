# Decisions (one line each, newest last)

- Track: Chef's Choice (re-check sponsor prizes at opening).
- Base MVP = sign in, badge, link card, scan, note, People, Person, Me. Everything else is an add-on after the 9pm checkpoint.
- Card key = SHA-256(salt + NFC tag UID). Only cards that read the same twice can be linked.
- A meeting is stored as two rows, one per person, so notes stay private and RLS stays simple.
- Look: badges and stamps, violet on lilac paper, light only. Fonts: Bricolage Grotesque, Instrument Serif Italic, Geist Mono, system UI.
- In-app AI (add-ons) = Grok via Supabase Edge Functions; the key lives only in Supabase secrets.
- Web join page (A3) uses anonymous sign-in, since Apple sign-in on the web needs extra setup.
- Cut: map, voice notes, photo at scan, 5-tab dock, notifications.
- Xcode project is generated by XcodeGen from project.yml (synced folder HiAgain/), bundle id com.kingston.HiAgain, team NNQ4DT9Z7Q. Info.plist and entitlements live in Config/.
- Non-app users see a profile through a public web badge page opened from a QR (A8). Husky IDs carry no NDEF link and App Clips need an App Store release, so neither is used.
- A8 evolved into QR meet: Me shows a QR to `meet.html?b=<slug>`; guest uses anonymous Supabase sign-in + `meet_via_web` to create dual meeting rows (`place_name` `QR code`). View-only public badge is superseded. GitHub Pages hosts static `web/`; Supabase handles reads/writes.
- meetings: only the note column is updatable (editing other_id would expose any profile). scan_card bounds lat/lng/place, returns only badge fields, and treats a repeat scan of the same person within 2 minutes as the same meeting. unlink_card() added for SupabaseService.unlinkCard().
- Known limit: card hashes use a salt shipped in the app and there's no scan rate limit. Fine for the demo; mention as future work.
- You tap someone's card once: Person shows one "Where you met" section, and a repeat scan shows "You've met before" instead of a met-again count. The DB contract is unchanged (scan_card still returns times_met).
- Design v3 replaces the violet look: paper/ink/stamp red, HELLO stickers, Archivo (static instances) + Caveat Brush + SF Pro, BadgeColor red/blue/green/yellow/pink/black. Live DB default is still 'lilac' until schema is re-run; the app always sends badge_color so it doesn't matter.
- Husky ID gives a stable NFC ID (same short code on repeat scans, tested Sat 1:15 PM). Other cards not yet recorded.
